## Held follow-ups (deliberately NOT planned yet)

- **Mirror double-store** (`cells` + `col_data` duplicate every CellValue,
  `mirror/write/cells.rs:119,175`): largest steady-state multiplier, M-L/MED —
  gated on plan 007's measured sizes.
- **CellData shrink** (~500-600B fixed/cell estimated): L/HIGH — gated on 007's
  `size_of` report.
- **Yrs `idToPos` removal / key packing** (~40-50% of per-cell Yrs cost):
  L/HIGH — document-schema change + migration; gated on measurements and a
  design pass.
- **Incremental per-sheet Yrs hydration** (ARCH-01): blockers inventoried
  (single transaction, ID allocator coupling, observer/undo suppression —
  the suppress mechanisms already exist); L/HIGH — design task for a
  judgment-tier model AFTER the diet plans land and 007 numbers exist.
- **Materialized-sheet LRU eviction**: requires kernel materialization-tracker
  coordination (Rust-side eviction alone would make the kernel skip
  re-materialization and show blank sheets). Needs a cross-boundary design.
- **Binary wire format for large range reads** (N-API JSON→binary): L/MED,
  server-path win.
- **`executeHydrateXlsx` extra byte copy** (kernel:2161-2178): S but
  intent-unclear (may guard against caller mutation) — investigate before
  removing.
- **CF-cache double clone per recalc; formula-text triplication; viewport
  delta per-cell merge; unbounded row-identity allocation**: round-2
  candidates, each S-M, none gating.

## Findings considered and rejected

- Freeing `raw_xlsx_bytes` early inside staging: staging holds `&self` by
  contract (failed staging must leave the engine retryable); rejected.
- Dropping `raw_xlsx_bytes` on the read-only path: it is the re-parse source
  for on-demand sheet materialization; load-bearing, not waste.
- Per-sheet `tracing` breadcrumbs: once per sheet, negligible; keep (they
  located the original OOM).
- AST cache eviction: verified correct (removed on delete/clear/sheet-delete);
  not a leak.
